# Roadmap and completion ledger

The normative phase definitions come from the
[Panefold system design](spec/SYSTEM_DESIGN.md#27-delivery-roadmap-and-governance). This ledger is
evidence-driven: **implemented** means repository code exists, **automated** means a repeatable test
or result exists, and **external** means the remaining proof requires a real platform, person,
independent organization, or third-party adopter. No row is promoted because the demo looks good.

## What “finish” means here

Repository-local work is merged only with implementation, tests, public boundaries, an ADR when the
ownership model changes, and synchronized machine-readable claims. Stable conformance additionally
requires evidence Panefold cannot ethically manufacture:

- manual NVDA, JAWS, VoiceOver, TalkBack, voice-control, forced-colors, and 400% task records;
- controlled physical 60 Hz and 120 Hz traces, heap/resource captures, and regression history;
- real crash, quota, corruption, permission, monitor-removal, and multi-screen runs;
- an independent threat/protocol/dependency review and signed release approval;
- real third-party adapter/plugin pilots with immutable certification artifacts.

Those items are not unfinished hidden code. They are explicit release inputs. Until they exist, all
packages and published profiles remain experimental and the ten stable hard gates remain
blocked/unresolved in [`conformance/gates.json`](../conformance/gates.json).

## Reproduce the current evidence

```bash
pnpm check
pnpm test:e2e
pnpm test:site:e2e
```

Executed browser results live in [`conformance/results`](../conformance/results/). Source evidence,
trace classification, and exact gate scope are generated into the remaining `conformance/` files.
Run results are narrow snapshots of their recorded environment; they are never silently widened
into a stable support promise.
