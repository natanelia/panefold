# Experimental command support

Version: `0.1.0` (experimental)

This manifest follows the `WorkspaceCommand` union in
`packages/model/src/commands.ts`. Every command below is implemented by the pure reference kernel,
but remains experimental. The machine-readable equivalent is
[`conformance/commands.json`](../conformance/commands.json).

All direct commands require a `CommandEnvelope` containing a stable command ID, origin,
human-readable label, optional base revision, and the command value. A stale base revision, invalid
input, or invariant violation returns a typed rejection without changing the snapshot. Successful
commands increment revision once and return patches plus a snapshot-based inverse.

| Command `type`             | Status                                 | Implemented behavior and current limitation                                                                                                                                                                                                                                                          |
| -------------------------- | -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `open-panel`               | Experimental                           | Adds a new panel to an existing group using a relational tab anchor. The panel ID must be new, `typeVersion` must be positive, and this command cannot create the first group in an empty workspace. Selection and activation default to enabled.                                                    |
| `close-panels`             | Experimental                           | Atomically closes one or more unique, closable live panels and creates recoverable records with caller-supplied IDs. Async close guards and application checkpoints are not implemented. Closing the final transient group may leave an empty workspace.                                             |
| `reopen-panel`             | Experimental                           | Restores the same panel ID from a recoverable record. It uses an explicit or former placement, falls back to the first live group if that group disappeared, and appends when a former tab anchor is stale. It cannot reopen without any destination group.                                          |
| `select-panel`             | Experimental                           | Selects a live panel in its owning group. Activation defaults to enabled.                                                                                                                                                                                                                            |
| `activate-panel`           | Experimental                           | Sets the live panel as global command target and updates serializable focus memory. The `focus` policy is accepted by the command contract; DOM focus execution belongs to the runtime/renderer and is not performed by the headless kernel.                                                         |
| `reorder-panels`           | Experimental                           | Moves a unique, non-empty subset within one group before or after one tab, or appends it. The relational anchor must remain outside the moving subset.                                                                                                                                               |
| `move-panel`               | Experimental                           | Moves one live panel to an existing group with a relational anchor; same-group reorder is allowed. Selection and activation default to enabled. It does not create a destination group.                                                                                                              |
| `split-group`              | Experimental                           | Moves a unique proper subset of one target group into a caller-ID'd adjacent group using a logical edge and ratio strictly between zero and one. It cannot split the entire group or pull panels from another group; same-axis canonicalization may intentionally remove the supplied split-node ID. |
| `merge-groups`             | Experimental                           | Moves every panel from one group into a different existing target group and removes the source group. Cross-surface roots are not supported; use `redock-surface` for a floating surface.                                                                                                            |
| `resize-split`             | Experimental                           | Replaces a split's allocation with one finite positive weight per child. Canonicalization deterministically normalizes weights to integer proportions totaling `1,000,000`; constraint resolution is handled by the geometry package.                                                                |
| `equalize-split`           | Experimental                           | Assigns equal normalized weights to all children of one split. Subset equalization is not implemented.                                                                                                                                                                                               |
| `create-floating-surface`  | Experimental                           | Detaches an entire floatable group into a new in-page floating surface with finite, non-negative bounds. The group must have a split parent, so the sole surface-root group cannot be floated. Browser popouts are not implemented.                                                                  |
| `move-floating-surface`    | Experimental                           | Updates finite `x` and `y` hints for an in-page floating surface that already has bounds. Viewport clamping and snapping are runtime concerns and are not performed by the kernel.                                                                                                                   |
| `resize-floating-surface`  | Experimental                           | Replaces an in-page floating surface rectangle with finite coordinates and non-negative dimensions. Panel minima, viewport clamping, and snapping are not performed by this command.                                                                                                                 |
| `maximize-surface`         | Experimental                           | Marks a normal in-page floating surface maximized and saves its current bounds for restoration. It does not calculate viewport-sized visual geometry.                                                                                                                                                |
| `restore-surface`          | Experimental                           | Restores a maximized in-page floating surface to its saved bounds. It rejects surfaces without a valid maximize record.                                                                                                                                                                              |
| `redock-surface`           | Experimental                           | Merges a single-group in-page floating surface into an existing docked group using a relational anchor, then removes the floating surface. Multi-group floating roots are not supported.                                                                                                             |
| `restore-workspace`        | Experimental                           | Atomically canonicalizes and validates a supplied typed snapshot, then commits it at the current revision plus one. Boundary decoding, schema migration, and untrusted-data limits must occur before the headless kernel.                                                                            |
| `undo-workspace-operation` | Experimental, stateful dispatcher only | Runs the latest snapshot-based inverse through `dispatchKernelState`. Calling it through `executeCommand` returns `HISTORY_REQUIRED`. History is bounded in memory and separate from panel-content undo.                                                                                             |
| `redo-workspace-operation` | Experimental, stateful dispatcher only | Replays the latest undone semantic command through `dispatchKernelState`. Calling it through `executeCommand` returns `HISTORY_REQUIRED`.                                                                                                                                                            |

## Intentionally absent

The current union does not claim commands for browser-window transfer, Picture-in-Picture,
distributed transactions, orphaned-surface recovery, group movement or swapping, collapsed-child
state, presets, imports, or dynamic plugins. Those capabilities remain unsupported until their
protocol, recovery, and conformance evidence exist.
