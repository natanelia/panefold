# Experimental command support

Version: `0.1.0` (experimental)

`WORKSPACE_COMMAND_TYPES` in `packages/model/src/commands.ts` is the authoritative runtime inventory.
Its compile-time assertion keeps the 36-entry tuple exhaustive with the `WorkspaceCommand` union;
the conformance harness checks the machine-readable
[`conformance/commands.json`](../conformance/commands.json) for exact parity.

Every entry below is implemented by the pure reference kernel and remains experimental. A semantic
command can exist without a supported product UI or operational adapter. In particular, external-
surface, remote-intake, persistence, and mobile-related commands do not certify browser popouts,
Picture-in-Picture, distributed collaboration, durable recovery, or mobile support.

Direct dispatch uses a `CommandEnvelope` with a stable command ID, origin, human-readable label,
optional base revision, and command value. Invalid input, stale revision, policy rejection, or
invariant failure returns a typed rejection without changing the snapshot. An accepted atomic
command increments revision once and returns patches and a transaction; eligible local commands
also return a snapshot-based inverse.

| Command `type`               | Execution             | Implemented semantic behavior and boundary                                                                                                                                                                                                                                   |
| ---------------------------- | --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `batch`                      | `executeCommand`      | Reduces an ordered set of batchable commands as one atomic transaction. History and remote-wrapper commands cannot be nested; any child rejection rejects the entire batch.                                                                                                  |
| `open-panel`                 | `executeCommand`      | Adds a caller-supplied panel descriptor at a relational tab placement. The destination group must already exist.                                                                                                                                                             |
| `duplicate-panel`            | `executeCommand`      | Copies a panel descriptor to a caller-supplied new stable ID and optional placement. Application-owned live content state is not cloned by the kernel.                                                                                                                       |
| `close-panels`               | `executeCommand`      | Atomically closes unique closable panels into caller-ID'd recoverable records. Async guards and checkpoint preparation must complete before dispatch.                                                                                                                        |
| `close-other-panels`         | `executeCommand`      | Closes the eligible peers of one retained panel in a group using deterministic caller-supplied closed IDs. Async guards remain pre-command work.                                                                                                                             |
| `close-panels-to-right`      | `executeCommand`      | Closes eligible panels after an anchor in current semantic tab order. Async guards remain pre-command work.                                                                                                                                                                  |
| `reopen-panel`               | `executeCommand`      | Restores the same panel ID from a recoverable record, using explicit/former placement or a canonical placeholder fallback.                                                                                                                                                   |
| `select-panel`               | `executeCommand`      | Selects a live panel in its owning group and can optionally activate it.                                                                                                                                                                                                     |
| `activate-panel`             | `executeCommand`      | Sets the global command target and serializable focus policy/memory. Actual DOM focus is renderer-owned.                                                                                                                                                                     |
| `reorder-panels`             | `executeCommand`      | Moves a distinct non-empty subset within one group using before/after anchors or append. An anchor cannot be in the moving subset.                                                                                                                                           |
| `move-panel`                 | `executeCommand`      | Moves one panel to an existing group with relational placement and optional selection/activation. It cannot bypass cross-document ownership.                                                                                                                                 |
| `move-group`                 | `executeCommand`      | Repositions an entire group beside another group with caller-supplied split identity, logical edge, and ratio. Cross-document movement requires prepared transfer.                                                                                                           |
| `split-group`                | `executeCommand`      | Moves a proper panel subset into a caller-ID'd adjacent group. Same-axis canonicalization may remove the supplied split-node ID.                                                                                                                                             |
| `merge-groups`               | `executeCommand`      | Moves every source-group panel into an existing target placement and removes the source. Cross-surface roots are rejected.                                                                                                                                                   |
| `swap-groups`                | `executeCommand`      | Swaps two group-node positions while preserving group identity. Cross-document ownership boundaries are rejected.                                                                                                                                                            |
| `resize-split`               | `executeCommand`      | Replaces a split's finite positive weights; canonicalization normalizes them. Pixel constraints and rounding are derived by geometry.                                                                                                                                        |
| `equalize-split`             | `executeCommand`      | Equalizes every direct child or an optional distinct direct-child subset.                                                                                                                                                                                                    |
| `collapse-child`             | `executeCommand`      | Adds a direct child to persisted semantic collapse state with an optional reason. Renderer affordances remain profile-specific.                                                                                                                                              |
| `restore-collapsed-child`    | `executeCommand`      | Removes a direct child from semantic collapse state. Renderer affordances remain profile-specific.                                                                                                                                                                           |
| `create-floating-surface`    | `executeCommand`      | Detaches an eligible group into an in-page semantic floating surface. The sole root group cannot float; this does not open a browser window.                                                                                                                                 |
| `move-floating-surface`      | `executeCommand`      | Updates finite position hints for an in-page floating surface. Snapping and viewport clamping are operational policies.                                                                                                                                                      |
| `resize-floating-surface`    | `executeCommand`      | Replaces finite floating bounds. Panel constraints, snapping, and clamping must be resolved before dispatch.                                                                                                                                                                 |
| `raise-surface`              | `executeCommand`      | Moves a floating surface to the end of canonical floating order. Platform window z-order is adapter-owned.                                                                                                                                                                   |
| `maximize-surface`           | `executeCommand`      | Records maximized semantic state and restoration bounds. Visual viewport geometry is adapter-owned.                                                                                                                                                                          |
| `restore-surface`            | `executeCommand`      | Clears minimized state or restores saved pre-maximize bounds when available.                                                                                                                                                                                                 |
| `minimize-surface`           | `executeCommand`      | Records minimized semantic state. Platform minimize behavior is adapter-owned.                                                                                                                                                                                               |
| `transfer-to-browser-window` | `executeCommand`      | Commits a group to a browser-window surface only with an already-prepared surface token and owner epoch. The optional surface adapter performs browser preparation/readiness; the kernel never opens a window.                                                               |
| `redock-surface`             | `executeCommand`      | Returns a surface root to an existing tab placement, enforcing an expected owner epoch for cross-document state.                                                                                                                                                             |
| `move-to-picture-in-picture` | `executeCommand`      | Moves one panel into a restricted semantic PiP surface with caller IDs, owner epoch, capability token, and `move` mode. The injected adapter path still requires a permission-capable browser and user activation.                                                           |
| `apply-workspace-preset`     | `executeCommand`      | Applies an identified typed snapshot in replace or merge mode. Input must already be bounded, decoded, migrated, and valid.                                                                                                                                                  |
| `restore-workspace`          | `executeCommand`      | Atomically canonicalizes and validates a supplied typed snapshot. Boundary decoding and migration happen before dispatch.                                                                                                                                                    |
| `import-workspace`           | `executeCommand`      | Imports an attributed typed snapshot in replace or merge mode after it crosses the persistence trust boundary.                                                                                                                                                               |
| `undo-workspace-operation`   | `dispatchKernelState` | Applies the latest bounded workspace inverse. Calling it through `executeCommand` returns `HISTORY_REQUIRED`; panel-content undo is separate.                                                                                                                                |
| `redo-workspace-operation`   | `dispatchKernelState` | Replays the latest undone semantic command. A new accepted semantic operation invalidates the redo stack.                                                                                                                                                                    |
| `apply-remote-transaction`   | `executeCommand`      | Applies one batchable semantic command with actor, transaction, surface, and epoch metadata plus bounded deduplication. Optional ecosystem authentication/coordination prepares this command; transport, keys, authorization, and domain conflicts remain application-owned. |
| `recover-orphaned-surface`   | `executeCommand`      | Moves an orphaned surface layout beside an application-selected recovery group using an expected owner epoch and caller-supplied split data.                                                                                                                                 |

## Operational boundaries

- Close guards, panel checkpoints, schema decoding, migration, permissions, popup creation, and
  surface preparation are asynchronous work outside the pure reducer.
- `transfer-to-browser-window` and `move-to-picture-in-picture` accept proof that preparation
  already occurred. `@panefold/surfaces` has an experimental injected popup/PiP preparation
  adapter, but semantic commands are never shortcuts around browser security or ownership.
- `apply-remote-transaction` is semantic intake and deduplication. `@panefold/ecosystem` can validate
  bounded packets, verify HMAC, and assign order through a single-writer port; an application must
  still provide transport, key lifecycle, authorization, durable coordination, and domain policy.
- `restore-workspace`, `import-workspace`, and presets accept typed snapshots only after the bounded
  persistence boundary has handled untrusted bytes.
- Undo/redo covers workspace structure and is intentionally separate from application content undo.
